# 服务器文件下载、GitHub 发布与新机器部署

> 本文用于**历史实验备份和旧权重恢复**。公开仓库默认已改成无私有包的从头训练路线，见 [README](../README.md)。新读者无需向我们领取训练好的模型或资产包。

## 1. 两种包各自放什么

**公开代码包**就是本仓库，已整理本地最终使用的源码、配置、README、结果统计和报告材料。可以上传 GitHub。它不包含完整模型、课程数据、预测全文、账号凭据或师兄模板。

**私有实验资产包**由下面的脚本在原服务器收集，包括已训练适配器、数据、原始初始回答、服务器代码副本和训练证据。应下载备份并通过适当途径提供给复现实验的人，不能把这个大包直接 `git add` 到公开仓库。`.gitignore` 已排除 `private/`、权重、压缩包和原始预测 CSV。

公开仓库的代码已经准备好；服务器下载主要补齐本地没有的已训练权重、完整 10K 监督语料，以及比对服务器是否有最后修改过的源码。

## 2. 在你自己的旧服务器上执行

把仓库中的 `tools/collect_server_assets.py` 上传到 `~/RAG/collect_server_assets.py`。这个脚本只用 Python 标准库，base 环境即可运行，不需要启动 GPU 或安装依赖。

先看必需文件是否齐全以及未压缩大小：

```bash
cd ~/RAG
python collect_server_assets.py --dry-run
```

生成基础私有包：

```bash
python -u collect_server_assets.py \
  --output ~/RAG/course_private_assets.tar.gz
```

脚本会核验本次 SFT adapter、RL step016 adapter 和原始 CFT 数据的固定哈希。缺少必需文件或哈希不同会明确报错，不会悄悄打出一个声称完整的包。

看到 `PRIVATE_ASSETS_READY` 后下载两个文件：

```text
~/RAG/course_private_assets.tar.gz
~/RAG/course_private_assets.tar.gz.sha256
```

建议本地放到 `RAG/server_results/复现/CLM/backup/`，不要放进公开仓库的版本控制范围。

### 更完整的保存方案

如果希望保留与当前 RL 训练完全一致的 SFT 基座，建议包含合并好的模型。这样无需重新导出，也避免因为基础模型 revision、序列化或导出环境改变而使校验不同：

```bash
python -u collect_server_assets.py \
  --include-merged-sft --include-evidence --include-optimizer \
  --output ~/RAG/course_private_assets_complete.tar.gz
```

此选项额外包含约 15 GiB 量级的合并 SFT 权重、较大的回答/日志证据，以及 RL 最终 Adam 状态。脚本在打包前报告实际大小；不包含重新可下载的 Qwen 和原版 LLaMA 全部权重。基础包也包含 SFT/RL 两份适配器，足以作为恢复模型的必要训练产物。

原服务器文件不被修改。输出文件已存在时脚本拒绝覆盖，换一个 `--output` 即可。

## 4. 哪些代码需要从服务器回收

本地已经包含四组实验使用的最终版本。收集脚本仍会把这些目录中的源码/配置打包进 `private/server_code/`，用于发现服务器上的最后修改：

```text
author_alignrag_course/course/
frozen_clm_full_answer/
clm_training_step4_data/
clm_training_step5/
clm_step6_2wiki/
clm_rl_grpo_pilot_v3/
clm_rl_step7_2wiki_v3/
```

恢复私有包后运行：

```bash
python tools/verify_assets.py --directory private
python tools/compare_server_code.py --private private
```

`changed` 和 `missing` 均为空说明服务器回收源码与当前发布快照一致。若不同，先根据结果定位具体文件并确认使用哪一版，不应直接覆盖发布快照或宣称两个版本完全一致。

早期 `clm_rl_grpo_pilot`、`_v2` 和旧的 step7 探针失败版不作为本次默认入口；最终评分来自 `pilot_v3` 与 `step7_2wiki_v3`。

## 5. 在新服务器恢复

1. 克隆公开仓库；准备 Linux 四卡环境并运行 README 中的依赖安装。
2. 在仓库根目录解压私有包，运行哈希校验。
3. 自行下载 Qwen2.5-7B-Instruct、原版 LLaMA-3.1-8B-Instruct；只有重新合成训练数据才需要 0.5B 弱模型。
4. 仅恢复旧实验时，复制 `configs/paths.historical.example.json` 为 `configs/paths.json`，填写解释器和模型路径；不要覆盖正在运行的新训练配置。
5. 若已有 `private/weights/sft_merged`，在仓库根目录执行 `ln -s sft_merged private/weights/Llama-3.1-8B-Instruct-CLM-SFT`，使历史配置的 `sft` 指向该链接；否则用训练环境执行 `tools/merge_sft.py` 合并到历史配置指定的新目录。带 `Llama` 的路径使旧推理代码选择正确采样温度。
6. 用 README 第 7 节的评测命令运行 5 条 smoke，再运行所需全量组；后三组默认使用历史配置中的共享 baseline。若新生成基线并希望比较它，后三组都显式传入同一新 baseline。

历史恢复的合并命令为 `~/.venvs/clm-training/bin/python tools/merge_sft.py --config configs/paths.json`，适配器和语料由历史配置指向 `private/`。默认从头训练配置则指向 `runs/` 的新产物，两套配置不能混用。

运行原 RL adapter 时，评测入口检查 SFT 权重文件哈希与 RL 训练时的 `spec` 是否一致。若重新导出导致不一致，恢复原服务器合并 SFT 模型，而不是绕过检查或把原版 LLaMA 当作 SFT 基座。新训练的 GRPO checkpoint 使用其相邻 `artifacts/spec.json` 记录的父模型。

只有本项目配置支持的四卡模式通过了历史 GPU 运行验证。迁移到其他硬件是新配置验证，不承诺原分数逐位重现。

## 6. 上传 GitHub 的具体步骤

由你在 GitHub 创建空仓库，例如 `rag-critic-grpo-course`。把本目录作为仓库根目录，**不要把整个原始 `RAG/` 目录上传**。

在本地新目录中运行：

```bash
python tools/check_release.py
python -m unittest discover -s tests -v
git init
git add .
git status --short
git commit -m "Add four RAG critic experiments and reproduction guide"
git branch -M main
git remote add origin <你创建的仓库地址>
git push -u origin main
```

本次整理没有创建远程仓库，也没有代替你执行 push。初次上传不包含私有包，不需要 Git LFS 存放数十 GB 的基础权重。适配器若以后单独发布，采用合适的模型分发方式并提供模型/数据来源。

目前成绩是执行者提供的记录。可在课程允许的范围内补上四次 Kaggle submission ID、截图和同一榜单划分说明。截图应放在 `results/`，不要暴露账号凭据；无需为了写报告重新运行全部实验。

## 7. 给报告/PPT 同学发送什么

发送 `docs/实现与实验报告.md`、`docs/报告与PPT写作提纲.md`、`results/kaggle_scores.png`（或 SVG）、`results/kaggle_scores.json`、`results/verified_training_summary.json`，以及准备好的 GitHub 地址。

同学写作不需要下载 8B 模型。若他要从头训练，发送 README 即可，由他自行准备基础模型和来源数据；只有恢复旧权重时才额外提供私有资产包。师兄的报告/PPT 只作结构参考，不要把其成员信息和实验结论纳入你们项目。

## 8. 如何向复现者分享资产包

当前仓库未设置公开资产下载链接。推荐维护者将基础包和校验文件放在同一个受限共享目录，通过现有课程联系渠道给需要运行实验的人发送访问方式；外部读者可以先通过 GitHub Issue 说明复现需求，再由维护者确认可提供的资源。无需让只阅读代码或写报告的人下载资产包。

分享前确认接收者可使用课程数据及相应模型。不要把包含课程测试集、完整回答和权重的整包直接加入公开 Git 仓库，也不要在公开 Issue 发布私人联系方式、提取码或访问凭据。若以后决定开放下载，应先确认各部分的分发条件，再在 README 添加实际可用的地址、版本、大小和 SHA256；当前没有可填写的真实下载链接。

向接收者发送以下内容即可：

1. GitHub 仓库地址及本次所用 commit。
2. `course_private_assets.tar.gz` 和 `course_private_assets.tar.gz.sha256` 两个文件的受限访问方式。
3. 本文第 5 节的旧权重恢复说明，以及 README 的环境、基础模型和第 7 节评测命令；不需要重跑 README 的合成/训练步骤。
4. 若要直接复用历史 RL 模型，补充提供原服务器合并 SFT 模型，或先验证重新合并结果符合 RL 父模型哈希。

2026-10-27 本地核验的基础包为 321,472,987 字节，内部 136 个清单文件均通过校验；93 个对应历史源码文件与公开快照一致。基础包 SHA256：

```text

```

接收者在 Linux 上先进入两个下载文件所在目录执行：

```bash
sha256sum -c course_private_assets.tar.gz.sha256
```

显示 `OK` 后，在新克隆的仓库根目录执行（把下载路径换成实际路径）：

```bash
tar -xzf /path/to/downloads/course_private_assets.tar.gz
python tools/verify_assets.py --directory private
python tools/compare_server_code.py --private private
```

默认解压得到 `private/`，不需要把内部文件逐个搬到旧服务器路径。之后按照 README 下载基础模型、填写 `configs/paths.json`、恢复 CLM8B 并运行 smoke。`.gitignore` 已排除该目录。

若对方只需要基线与 Frozen CLM，可以从课程来源取得测试数据和模板，自己生成 Qwen 初始回答；不必领取整个包。若要采用新数据自行训练，则需准备输入结构并更新相应选择与来源记录，不能把当前入口当作任意数据集的通用训练器。
