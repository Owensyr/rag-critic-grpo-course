# 代码导航与复现范围

## 1. 两层代码

`pipelines/` 是实际历史实验的源文件快照，来源与 SHA256 列在 `provenance/source_inventory.json`。保留其旧 README、参数和来源记录，以便审查实现。旧 README 中“尚未上服务器”的文字是当时打包状态；当前运行入口以根目录 README 为准。

历史驱动含特定文件哈希和旧目录布局，直接运行可能因缺数据或路径不同而停止。这是完整性检查，不是让复现者手工删除检查的提示。

`tools/` 是新整理的便携入口：复制工作目录、绑定本机路径与实际输入、记录变更，再调用历史算法。不会覆盖原有实验目录，也不会把新运行伪装成原运行哈希。它们通过本地 CPU 检查，但没有在本地重新执行四卡训练。

## 3. 如何重新构造训练数据

默认路线已经改为从基础模型和原始数据开始，不需要历史私有包。依照 README 获取作者五数据集和课程测试集，再执行：

```bash
python3 tools/prepare_data.py course \
  --test data/raw/course/test.json --sample data/raw/course/sample_submission.csv
python3 tools/prepare_data.py sft
python3 tools/prepare_data.py grpo

python3 tools/prepare_workdir.py synthesis --config configs/paths.json \
  --data-dir data/prepared/sft --accept-new-data --output runs/synthesis
python3 tools/launch.py --workdir runs/synthesis
```

默认 `data/raw/author` 下需有 `2WikiMultiHopQA/ASQA/NaturalQuestions/PopQA/TriviaQA` 五个目录，各含 `train.json`、`test.json`。可以通过 `--author-root` 指向别处。输出目录不能已存在。SFT 选题仍调用未修改的历史 `pipelines/synthesis/build.py`，输出选题 JSONL、审计和预览。

`--accept-new-data` 显式接受新合成/GRPO选题，检查数据审计，记录新输入哈希并封存新工作目录；`--accept-new-corpus` 接受本次新生成的 CFT 语料。SFT 工作目录也绑定本次基础模型 config 哈希。它们不会更改历史快照的哈希，也不会把新结果标成旧实验。

GRPO 新入口只需作者 TRAIN、SFT 选题和评测问题文件，重新抽取 128+128 条并隔离 gold；不依赖旧 reward32、smoke、pilot 选题。可用 `--exclude-questions` 排除自己开发奖励时见过的题。训练逻辑、奖励协议、停止检查和父模型哈希绑定保持历史实现。最终 CSV 仍完整保留 Qwen 输出。

`configs/paths.historical.example.json` 仅用于已有旧权重与旧输入的归档恢复。默认从头训练路线使用 `configs/paths.example.json`，不需要历史资产。

## 4. 运行与验证边界

| 层次 | 已完成 | 尚未声称完成 |
| --- | --- | --- |
| 历史 GPU 运行 | 四组实验、10K SFT、16 轮 GRPO、12,576 条 RL 评测 | 多种子显著性验证、其他 GPU 配置 |
| 当前发布整理 | 来源文件匹配、Python 语法、CPU 协议/导出/命令测试 | 便携入口在新服务器的完整 GPU 重跑 |
| Kaggle | 执行者提供四组成绩 | 独立登录核实 submission ID、隐藏判分代码 |
| 文件完整性 | 最新 RL CSV 行数/顺序/原文/hash 校验 | CSV 完整就意味着内容全部正确 |
| 数据隔离 | 规范化问题去重，分离 RL gold | 全部语义改写/事实重叠均被排除 |

## 5. 不应加入主实验依赖的历史内容

短答案提取与 unknown 修复、早期失败的 RL 校准版本、旧版 LoRA 效果探针、另一套四 GPU 分片基线，不是本次四个全文提交分数的必需执行路径。它们没有混进默认公开入口。

这里没有新增在线检索器、自适应停止器或其他未经验证的 RL 算法。训练日志、诊断和 CSV 由各运行入口生成到 `runs/` 下。
