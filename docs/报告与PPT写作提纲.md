# 给报告与 PPT 作者的写作提纲

本材料参照所提供课程报告和 PPT 的章节组织：背景与问题、研究思路、方法实现、实验比较、总结展望和团队贡献。这里仅参考结构，不沿用模板中的其他方法成绩、个人信息或未经核实的背景数字。

## 一、建议标题与中心论点

**建议标题：基于批判反馈与强化学习的检索增强问答改进。**

副标题可为“Qwen 与 CLM8B 在 2WikiMultiHopQA 上的四组对照实验”。

中心论点：提供检索文档之后，回答仍可能存在实体连接和推理错误；专门训练批判器可改善问答表现。我们进一步尝试用最终问答结果对批判器做 GRPO，小规模实验得到额外的小幅提升。

避免把主结论扩大成“解决大模型幻觉问题”。本项目测量的是特定问答任务和评分流程下的表现，未测量所有幻觉类别。

## 五、可以直接放进结果页的文字

> 在本次课程评测中，原版 LLaMA 批判器将 Qwen 基线的 Kaggle 得分从 0.45507 提升至 0.46382。使用 10K 数据监督微调后，CLM8B 的得分提高到 0.51311，构成主要增益。在此基础上进行小规模 GRPO 后，得分进一步达到 0.51523，比 SFT 组增加 0.212 个百分点。考虑到单次运行、训练规模、评分器误差和引擎设置差异，该结果说明强化学习具有进一步探索的价值，但尚不能认为增益稳定或统计显著。

## 六、常见答辩问题

**为什么不是只训练 2Wiki？** 为了沿用跨任务学习批判能力的思路，使用五数据集构造 SFT；课程最终只评测 2Wiki。RL 则只用另行抽样的 2Wiki 训练题。

**第二组和第三组有什么区别？** 第二组使用原版 Instruct LLaMA 直接批判；第三组用专门的“批判 + 改进参考”数据做过本项目 SFT。

**强化学习更新 Qwen 吗？** 不更新。冻结 Qwen 根据不同批判修订回答，只更新 SFT CLM 上新增的 RL LoRA。

**为什么 GRPO 分数只增加一点？** 实际只有 128 道训练题、15 次有效更新，且奖励由模型判定、KL 约束较保守。当前没有消融证据确定哪一个因素是主要原因，应作为可能解释，而不是确定结论。

**是否完成自动停止？** 实现的是达到一次批判修订预算后自动结束，没有按质量自适应继续/停止。若要实现完整自适应 Agent，需要额外设计停止准则并重新测评。

**Kaggle 准确率等于幻觉率的反面吗？** 不能这样换算。答案命中可能忽略长文本中的其他错误，Kaggle 的内部指标也未独立核实。

**模型说 unknown 是否因为提取脚本弄错？** 四组最终成绩都采用完整原始回答提交，不经过短答案抽取。正文的拒答是模型输出的一部分。

**是不是论文所有设置完全复现？** 是基于论文方法的课程复现。训练数据重构、ASQA 支持口径、硬件训练设置和课程评测集存在明确差异，GRPO 是本项目新增实验。

**重新运行为什么分数不完全一样？** 随机采样、GPU 数值、引擎批处理、基础权重版本和重新合成的数据都可能改变结果；应记录配置和哈希，而不是强行覆盖旧分数。
